# /adr
1. Describe context and options, including at least one credible alternative.
2. Document trade-offs, constraints, testing needs, security and migration impact.
3. Write an ADR in `docs/architecture/decisions` with status Proposed.
4. Ask owner approval before promoting to Accepted or implementing a consequential change.
