# ScreamPad Audio 2ch unsigned package prototype

This is an isolated packaging experiment for [ADR 0016](../../../docs/architecture/decisions/0016-macos-integrated-audio-component.md). It does not install a driver, alter CoreAudio, change ScreamPad production code, sign/notarize an artifact, or distribute one. Do not put its unsigned package into a public ScreamPad installer.

## Pinned inputs and changes

- Upstream: [ExistentialAudio/BlackHole](https://github.com/ExistentialAudio/BlackHole), tag `v0.7.1`, commit `e2b22aaaba4e507a097131704bf96dabc004d9cf`.
- Patch: [`blackhole-v0.7.1.patch`](blackhole-v0.7.1.patch). It sets the ADR's bundle/device/box/model/mirror/factory IDs, a two-channel ScreamPad name, ScreamPad manufacturer, macOS 14 deployment target, no upstream signing team, and no eligibility as system default device. It changes no audio processing algorithm.
- Icon input: `src-tauri/icons/icon.icns` from this ScreamPad revision, copied into the temporary source tree as `ScreamPadAudio.icns`.
- Prototype package and bundle version: `0.7.1.1`. This is not a public release version commitment.
- Package contains one `ScreamPadAudio2ch.driver`, upstream GPL license and a modification/attribution note. It has **no installer scripts**.

The upstream installer and uninstaller scripts are never executed or packaged. The build recipe archives the pinned upstream commit, applies the patch in a temporary directory, runs `xcodebuild` without code signing, and packages the result with `pkgbuild --root` and an explicit package ID. It then expands the package to check IDs, payload paths, attribution and architecture slices. Output logs and the unsigned package stay outside Git.

`pkgutil --payload-files` may show AppleDouble `._` metadata entries generated by macOS packaging. The verifier allows those only for the owned bundle, rejects other providers/paths, and checks that `pkgutil --expand-full` produces only the expected driver bundle.

## Run on macOS with Xcode

```sh
git clone --branch v0.7.1 https://github.com/ExistentialAudio/BlackHole.git /tmp/blackhole-v0.7.1
./packaging/macos/screampad-audio-2ch/build-prototype.sh /tmp/blackhole-v0.7.1 /tmp/screampad-audio-output
```

The checkout must be clean and at the pinned commit. The output directory must not already contain the package. `verify-prototype.py <package>` can inspect it again without installation. Record the ScreamPad commit, upstream commit, Xcode version, package SHA-256 and logs when sharing results. The patch and recipe, together with pinned upstream source, are the corresponding prototype source; production source publication remains a separate release gate.

## Evidence boundaries

The verifier proves only static package contents. It cannot prove that CoreAudio loads the driver, that it coexists with original BlackHole, that a call app receives audio, or that signing/notarization/install/repair/uninstall work. All those are **NOT VERIFIED** until separate authorized tests complete. See the [compatibility checklist](../../../docs/engineering/macos-audio-component-compatibility-checklist.md).

## Local result (2026-10-26)

On macOS 26.2 arm64 with Xcode 26.2, the pinned upstream checkout produced a 147 KB unsigned universal package. `verify-prototype.py` passed on the final package; `pkgutil --check-signature` reported `Status: no signature`; the Xcode build log contained no warnings or errors. The package SHA-256 was `95a2f29012882a9b2c3acc90d358b2627bfd50d1308ffc1c15483b5490501a5d`. Eight inspector tests passed, including rejection of original BlackHole identity, another provider's payload, installer scripts and AppleDouble files in the expanded payload. The package stayed under `/tmp`; it was not installed or committed.
