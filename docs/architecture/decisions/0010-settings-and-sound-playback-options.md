# ADR 0010: Application Settings and Per-Sound Playback Options

- Status: Accepted (owner approved on 2026-10-25 with the clarifications below)
- Date: 2026-10-25
- Owner: project owner

## Context
Schema 1 has one table, `sounds`. Three product needs have no storage yet:
- the chosen UI language (ADR 0008 deferred the switcher until a `settings` migration is approved);
- a master volume that survives restarts;
- per-sound options: a gain trim and what happens when a sound is triggered again while it is still playing.

Rules that apply: migration `0001` is released and must not be edited; schema changes are forward-only migrations that need
owner approval, a `SHIPPED_CHECKSUMS` entry and a frozen `schema_v2.sql` fixture. The existing pre-upgrade `VACUUM INTO` backup
covers the 1 -> 2 step.

## Options
### Settings storage
- **A: typed single-row table `app_settings`** (recommended). One row, `CHECK (id = 1)`, one typed column per setting, every
  column with a default and a range check. Invalid values are rejected by the database.
- **B: key-value table.** Adding a setting needs no migration, but values are untyped text, ranges cannot be enforced by
  `CHECK`, and typos in keys fail silently. Rejected.

### Per-sound options
- **A: new columns on `sounds`** via `ALTER TABLE ... ADD COLUMN` (recommended). The immutability trigger lists the media
  columns explicitly, so the new columns stay editable. Existing rows receive the defaults.
- **B: separate `sound_options` table.** An extra join and a second row to keep in step with every sound, for options that are
  always present. Rejected until options become sparse or numerous.

## Proposed schema 2 (SQL)
```sql
ALTER TABLE sounds ADD COLUMN gain_millibels INTEGER NOT NULL DEFAULT 0
    CHECK (gain_millibels BETWEEN -6000 AND 600);
ALTER TABLE sounds ADD COLUMN play_mode TEXT NOT NULL DEFAULT 'overlap'
    CHECK (play_mode IN ('overlap', 'restart', 'ignore', 'toggle'));

CREATE TABLE app_settings (
    id                    INTEGER PRIMARY KEY CHECK (id = 1),
    language              TEXT    NOT NULL DEFAULT 'system'
        CHECK (language = 'system' OR (length(language) BETWEEN 2 AND 8 AND language NOT GLOB '*[^a-z-]*')),
    master_gain_millibels INTEGER NOT NULL DEFAULT 0 CHECK (master_gain_millibels BETWEEN -6000 AND 0),
    updated_at_ms         INTEGER NOT NULL DEFAULT 0 CHECK (updated_at_ms >= 0)
) STRICT;
INSERT INTO app_settings (id) VALUES (1);
```
Units: gain in millibels (1/100 dB) so values are integers.

## Decision
Approved as proposed, with these owner clarifications:
- **Settings:** a typed single-row `app_settings` table, no key-value store and no generic settings framework. `language` is
  `system` or a supported BCP 47 tag (`en`, `uk`; the list is checked in the application layer, the database only checks the
  tag shape). Defaults: `system`, 0 dB. Settings persist across restarts. The row `id = 1` is created by the migration.
- **Missing settings row:** treated as an integrity error (`StorageError::Corrupt`), never hidden behind invented defaults and
  never silently recreated. There is no repair procedure yet; the UI shows the error and the language falls back to the system
  language for that run.
- **Per-sound options:** `gain_millibels` (-6000..=600) and `play_mode` columns on `sounds`; the media columns stay immutable.
  The values are Rust types (`Millibels`, `PlayMode`) and typed IPC DTOs; the business logic never compares magic strings.
- **Gain:** master -60..0 dB, sound -60..+6 dB, millibels = dB x 100, linear gain = 10^(dB/20). Master and sound gain are applied
  independently and multiply. -60 dB is not mute; there is no mute yet. Overload protection stays the mixer's hard clamp
  (ADR 0006); a limiter needs its own decision.
- **Play modes** (default `overlap`), decided by `PlaybackService`, never in the audio callback:
  - `overlap`: start another voice. The mixer has a fixed upper bound of 32 simultaneous voices (`MAX_VOICES`); a play beyond it
    is rejected by the callback, counted in `rejected_plays` and nothing else is stopped.
  - `restart`: stop every voice of this sound, then start a new one from the beginning.
  - `ignore`: do not start while a voice of this sound is active.
  - `toggle`: stop every active voice of this sound, otherwise start one.
- **Loop** is deferred to its own ADR and migration. No loop columns or logic now.
- New typed commands: `get_settings`, `update_settings`, `set_sound_options`; DTOs generated by tauri-specta (ADR 0004). The
  frontend loads settings before the first render so the language does not flash.

## Consequences
- Playback must track voices per sound: `engine.play` needs the sound id and the mixer must report voice ids and end events so
  `restart`, `ignore` and `toggle` can be decided in `PlaybackService` (not in the audio callback).
- The mixer applies per-voice gain (already supported) and master gain (already supported); no new real-time work, no SQLite on
  the audio thread.
- Gain above 0 dB can clip; the existing soft limiting/clamping behaviour must be checked with a test at +6 dB.
- Downgrading to an older build is not supported (forward-only migrations).

## Validation (to be done after approval)
- Frozen fixture `schema_v2.sql`, `SHIPPED_CHECKSUMS` entry, upgrade test 1 -> 2 with data, rollback on failure.
- Constraint tests: out-of-range gain, unknown play mode, wrong storage type, second settings row, deleting the settings row.
- Verified so far (executed, SQLite CLI, in memory, on the real `0001` schema): existing rows get the defaults; valid updates pass;
  media columns remain immutable; invalid gain, play mode, language and a second settings row are rejected; `integrity_check` ok.
  This does not test the Rust migration runner.
- NOT VERIFIED: behaviour on Windows, the audible effect of gain and play modes.

## Implementation notes (2026-10-25)
- Migration `0002_settings_and_sound_options.sql` with the frozen fixture `schema_v2.sql` and a `SHIPPED_CHECKSUMS` entry. The
  pre-upgrade `VACUUM INTO` backup covers 1 -> 2 (tested).
- Domain: `SoundGain` (-6000..=600), `MasterGain` (-6000..=0), `PlayMode`, `Language`; the IPC layer uses `PlayModeDto` and a
  language string validated by `Language::parse`. Stored values that no longer parse are `StorageError::Corrupt`.
- `PlaybackService::play(id)` reads the sound's stored gain and mode (one read-only query per trigger) and decides with
  `PlayMode::on_trigger`. The decision and the engine call that carries it out are serialized by one lock, so simultaneous
  triggers of one sound cannot both decide on stale information (tested, mutation-checked).
- `AudioEngine` tags voices (`play_tagged`), answers `playing(tag)` and `stop_tag(tag)` from its own thread, and treats a voice
  that was asked to stop as no longer playing even while it fades out. Voice bookkeeping lives on the engine thread; the audio
  callback is unchanged (the counting-allocator test still passes).
- The engine keeps the linear master gain and applies it to every stream it opens, so a device change does not reset it.
  `update_settings` stores first, then applies; the saved value is applied at startup.
- The persisted master gain cannot be below -60 dB, but the engine accepts 0.0 so tests on a real device stay silent.
- At the 32-voice limit the audio callback refuses the new voice and counts it (`rejected_plays`); nothing else is stopped. A
  stopped voice keeps its slot for the 5 ms fade, so a `restart` at the limit can be refused as well.
- New commands: `get_settings`, `update_settings`, `set_sound_options`. `play_sound` now returns `started`, `restarted`,
  `stopped` or `ignored`. New error kind `invalidSetting`.
- UI: a settings panel (language, master volume) and per-sound options (gain, play mode) in `src/features/settings` and
  `src/features/library`. Sliders edit whole decibels and save 300 ms after the last change or on blur. The stored language is
  applied before the first render (`main.tsx`); if the settings cannot be read, the system language stays.

## Limits
- NOT VERIFIED: the look and behaviour of the new controls in the running app (keyboard flow, narrow window); audible gain and play modes on any hardware (checklist rows 12-14); Windows and Intel macOS.
- A damaged or missing settings row has no repair procedure yet; the commands report `storageCorrupt`.
